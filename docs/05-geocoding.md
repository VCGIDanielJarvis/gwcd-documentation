# Geocoding: Geocoded vs. Non-Geocodable Data

## Process

1. Each record's address is concatenated (`Address1, City, VT, Zip`) and
   geocoded against the state's E911 composite address locator.
2. Any record whose address **fails** to geocode is retried using **just the
   town name**, geocoded to that town's **centroid** point instead.
3. A record that fails **both** steps (no usable address, and no
   recognizable/geocodable town name) is **kept, not dropped** — it has no
   geometry, but the (reused, not-a-schema-change) `ConcatAddress` field is set
   to a plain-language reason instead of an address: `"EXCLUDED - Out of State
   Address, Not Geocoded"` or `"EXCLUDED - Address Could Not Be Geocoded"`.
   Centroid-fallback records get `"<town> Centroid"` in that same field.
4. All surviving points with geometry (address-level matches + centroid
   fallbacks) are spatially joined to town boundaries to assign a `TOWNNAME`.
   Records with no geometry at all have no `TOWNNAME`, and are excluded from
   the public/exceedance pipeline by the "resolvable Vermont town required"
   rule in [03-filtering-criteria.md](03-filtering-criteria.md) — but they
   still exist in `GroundwaterChemistry_GWCDPoints`, tagged as above.

**Practical implication**: because of the centroid fallback, the overwhelming
majority of records end up with a town assignment even when the home address
itself can't be pinpointed. True geocoding failure (a record with no
`TOWNNAME` at all) should be rare — it requires the town/city field itself to
also be unusable (blank, out-of-state, unresolvable typo not covered by the
alias table, etc.).

## Is there a single view with both geocoded and non-geocodable results?

Yes — the **`GroundwaterChemistry_ExcludedRecords`** CSV, published to ArcGIS
Online on every weekly run. It is generated by scanning
`GroundwaterChemistry_GWCDPoints` for the `ConcatAddress` markers described
above, and includes:

- Every record that failed to geocode entirely (out-of-state addresses never
  attempted, and Vermont addresses/towns that just didn't match anything).
- Every record that only reached **town-centroid precision** — these records
  **do still count toward the public map's town/analyte statistics** (they
  have a valid `TOWNNAME`); they're included here purely so a privileged
  reviewer can see which records' map positions are low-precision, not because
  they're excluded from anything.

The report includes the full schema of `GroundwaterChemistry_GWCDPoints`, plus
the point's longitude/latitude (where it has one) and a plain-language
`GeocodeOutcome` column (`"Out-of-state address, not attempted"`, `"Address
could not be geocoded"`, or `"Geocoded to town centroid only (reduced spatial
precision)"`). It is **not** a list of every record excluded from the public
app for any reason — rejected results, institutional clients, small-sample
suppression, etc. are a separate, unrelated set of filters (see
[03-filtering-criteria.md](03-filtering-criteria.md)) and are intentionally
not part of this report.

This report is for privileged internal review only — it isn't consumed by
either Experience Builder app.

## Table reference

| Table/item | Geocoded? | Filtered to private-water scope? | Use for |
|---|---|---|---|
| `GroundwaterChemistry_GWCDrawdata` | No | No | **Full, unfiltered dataset** — best for state-level totals/rates that don't need geometry or town-level slicing |
| `GroundwaterChemistry_GWCDPoints` | Yes (address, town centroid, or tagged-not-geocoded) | Yes | Town-level slicing with unsuppressed counts — best source for a grant-reporting dashboard |
| `GroundwaterChemistry_GWCDPointTableExternal` | Yes | Yes, plus deduplicated + suppressed (<20 samples/group hidden) | What the public app displays — don't use this for totals, you'll undercount |
| `GroundwaterChemistry_ExcludedRecords` (AGOL CSV) | Partial/no, by definition | N/A | Reviewing which records have no or low-precision geocoding |

If you need one dataset with **both** full records and a town flag, join
`GroundwaterChemistry_GWCDrawdata` to `GroundwaterChemistry_GWCDPoints` on
`Record_uid` — this gives every raw record, with a `TOWNNAME` where one could
be determined and NULL where it couldn't.

For a dashboard that needs **both** state-level and town-level views: start
from `GroundwaterChemistry_GWCDrawdata` (or the raw SQL source) for the
state-level numbers — it needs no geocoding — and use
`GroundwaterChemistry_GWCDPoints`'s `TOWNNAME` field for the town-level slice.
